Help and restore

Short guides for each kind of destination, and how to restore. The full guide is BACKUPS.md in the project folder.

R2Cloudflare R2
  1. In the Cloudflare dashboard open R2 → Create bucket (e.g. nbte-backups).
  2. R2 → Manage API tokens → Create API token with Object Read & Write on that bucket. Copy the Access Key ID and Secret Access Key.
  3. Add a destination: kind S3-compatible, bucket nbte-backups, region auto, endpoint https://<account-id>.r2.cloudflarestorage.com.
  4. Add to .env, restart, then press Test connection:
BACKUP_S3_R2_ACCESS_KEY_ID=your-access-key-id
BACKUP_S3_R2_SECRET_ACCESS_KEY=your-secret-access-key
BACKUP_S3_R2_ENDPOINT_URL=https://<account-id>.r2.cloudflarestorage.com
BACKUP_S3_R2_REGION=auto
SBSupabase Storage
  1. In Supabase open Storage → New bucket (private), e.g. nbte-backups.
  2. Project Settings → Storage → S3 Connection: copy the endpoint and region, then New access key.
  3. Add a destination: kind S3-compatible, bucket nbte-backups, endpoint https://<project-ref>.supabase.co/storage/v1/s3, your project's region, addressing style Path.
BACKUP_S3_SUPABASE_ACCESS_KEY_ID=your-access-key-id
BACKUP_S3_SUPABASE_SECRET_ACCESS_KEY=your-secret-access-key
BACKUP_S3_SUPABASE_ENDPOINT_URL=https://<project-ref>.supabase.co/storage/v1/s3
BACKUP_S3_SUPABASE_REGION=eu-west-2
S3AWS S3
  1. Create a private bucket (block all public access; turn on versioning if you like).
  2. Create an IAM user with a policy allowing s3:PutObject, s3:GetObject, s3:DeleteObject and s3:ListBucket on that bucket only. Create an access key for it.
  3. Add a destination: kind S3-compatible, the bucket, its region; leave the endpoint blank.
BACKUP_S3_AWS_ACCESS_KEY_ID=AKIA...
BACKUP_S3_AWS_SECRET_ACCESS_KEY=your-secret-access-key
BACKUP_S3_AWS_REGION=eu-west-2
B2Backblaze B2
  1. Create a private bucket, then an Application Key limited to it.
  2. Endpoint: https://s3.<region>.backblazeb2.com (shown on the bucket page); region e.g. us-west-004.
BACKUP_S3_B2_ACCESS_KEY_ID=your-key-id
BACKUP_S3_B2_SECRET_ACCESS_KEY=your-application-key
BACKUP_S3_B2_ENDPOINT_URL=https://s3.us-west-004.backblazeb2.com
USBA USB or external drive
  1. Plug the drive into the server. Desktops mount it automatically under /media/<user>/<label>; on a server run sudo mkdir -p /mnt/backup && sudo mount /dev/sdb1 /mnt/backup (add it to /etc/fstab to keep it after a restart).
  2. Make it writable by the user the system runs as, e.g. sudo chown www-data /mnt/backup.
  3. Add a destination: kind USB or external drive, then pick it from the list (press Look again if you just plugged it in).
  4. If the drive is unplugged, backups to it fail clearly — they never fill the server's own disk.
DIRA folder on this server
  1. Pick a folder outside the project, ideally on another disk: sudo mkdir -p /var/backups/nbte && sudo chown www-data /var/backups/nbte.
  2. Add a destination: kind Folder on this server, path /var/backups/nbte. No keys are needed.
  3. A local copy alone does not survive a lost server: add an off-site destination too.
KEYEncryption key

When encryption is on and BACKUP_ENCRYPTION_KEY is set, every file is encrypted (AES-256-GCM) before it leaves the server. Generate a key once and keep a copy somewhere safe off the server — without it, encrypted backups cannot be restored.

python -c "import os,base64;print('BACKUP_ENCRYPTION_KEY='+base64.urlsafe_b64encode(os.urandom(32)).decode())"

↺Restoring (superusers only)

A real restore overwrites live data, so it is never a button. A superuser runs it on the server:

  1. Run a restore drill of the backup first and read its report.
  2. Tell users, then stop the web server and the Celery worker.
  3. Run the restore. The current database file and file folders are kept aside as *.before-restore-<time>.
  4. Run migrate and check, start the services and sign in to confirm.
# check a backup without touching anything
python manage.py restore_backup --drill <run id>

# real restore of a run listed above
python manage.py restore_backup <run id> --as <superuser e-mail> --confirm <backup label>

# the database is gone: restore from a downloaded backup folder
python manage.py restore_backup --from-dir /path/to/nbte-backup-... --confirm <backup label>
